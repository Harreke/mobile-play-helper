# 原始音视频和拖拽诊断记录

工具条“开始录制（含手机声音）”会建立 `%TEMP%/MobilePlayHelper/日期时间-进程号-唯一编号/`，再次点击“停止录制”收尾后打开资源管理器并选中 `phone.mkv`。映射中按住 F1 临时使用鼠标即可点击按钮。等待关键帧期间也可停止。

- `phone.mkv`：直接封装收到的手机视频和声音，不进行画面/声音重新编码，不包含 PC 工具条或诊断箭头。采用 Matroska 容器以保留 H264/HEVC、Opus/AAC 等原始编码。
- `events.csv`：原始诊断事件。关闭诊断箭头不会关闭日志；日志记录的是 PC 输入和映射器的触点，不是游戏内部焦点。
- `metadata.json`：编码、分辨率、时间原点、视频/音频包数量、`stop_reason` 结束原因及 `incomplete` 标记。录制期间为 `true`；正常结束才改为 `false`。异常关闭可能只保留最后一次刷盘之前的数据。

手机音视频未就绪时拒绝开始，避免静默生成无声录像；手机系统/应用本身禁止音频采集的内容不能保证被录入。录制从点击之后的第一个视频关键帧开始，等待期间日志照常保存；静止画面可能需要等待画面变化。手机流断开、分辨率或编码配置改变会结束当前文件，可以再次开始新文件。录制采用后台文件写入，队列超过 32 MiB 或 16384 条时停止录制并提示，不静默丢弃日志，也不打断投屏。

## 时间及字段

`pc_time_us` 是 SDL 单调时钟微秒，用于排序输入、触摸和帧事件。`phone_pts_us` 是独立的手机媒体时钟：`packet` 行为收到的压缩包 PTS，其余行为最近已显示视频帧的 PTS。没有已显示帧时为 AV_NOPTS_VALUE（-9223372036854775808）。

对应视频位置（秒）= `(phone_pts_us - metadata.media_origin_pts_us) / 1000000`。视频开始前的日志允许出现负数；不能将 PC 时钟直接减手机时钟。两个已显示帧之间的多个输入共享手机 PTS，使用 PC 时钟差可分析其先后和间隔。CSV 的跨线程入队顺序用于保留同刻事件顺序。

事件：

| event | id / action / x / y 含义 |
| --- | --- |
| mouse | x/y 为相对鼠标增量 |
| key | id 为 SDL 物理扫描码；action 为按下 1/松开 0；x 为 repeat |
| button | id 为 SDL 鼠标按钮；action 为按下 1/松开 0；x/y 为窗口坐标 |
| touch | id 为映射触点编号（1 是视角、0 是摇杆）；action：0 按下、1 松开、2 移动；x/y 为手机帧内归一化坐标 |
| refresh | 按 · 请求刷新；x/y 为视角原点，随后可观察独立 UP、DOWN 指令是否被队列接收 |
| frame / heartbeat | 显示帧更新 / 每 500ms 状态采样 |
| mapping_start / mapping_stop / mapping_suspend / mapping_resume | 映射状态切换后的状态 |
| arrow_toggle | Num Lock 切换后的箭头状态 |
| window | id 为 SDL 窗口/退出事件编号；状态为处理事件前的快照 |
| binding | 开始录制时的配置；id 为扫描码，action 为触点编号，x/y 为配置坐标 |
| packet | id：0 视频/1 音频；action 为 FFmpeg 包标志（bit 0 是关键帧），x 为字节数；其他列为空 |
| record_start / record_stop | 手动开始/停止标记；断线停止应结合 incomplete 和 packet 末尾分析 |

`queue_accepted=1` 仅表示 PC 控制队列接收，不是 Android 或游戏确认；0 表示入队失败，-1 表示不适用。`touch` 行中的 `look_down` 是该动作尝试之前的映射器状态。

其他列保留映射开关、暂停、窗口失焦、SDL 相对鼠标模式、视角按压、待处理增量、刷新阶段、重定位和拒绝次数、已显示帧数、最后显示帧的 PC 时间、视角原点、灵敏度、半径和诊断箭头开关。

## 诊断方法

先定位视频中卡视角的时间，再取同时间附近的日志：

1. `mouse` 停止：检查窗口失焦、相对鼠标模式及暂停事件。
2. `mouse` 持续但 `touch` 停止：检查映射状态、待处理增量和刷新阶段。
3. `touch` 的入队结果为 0：检查控制队列/连接；不能归因为游戏抢焦点。
4. 视频 `packet` 持续而 `frame` 停止：提示 PC 解码或显示链路可能停顿。
5. `touch` 持续且入队成功、画面仍更新，但游戏视角不动：可能是手机注入或游戏接收环节；只能结合视频和 · 刷新后的表现继续判断，不能只据 PC 日志认定根因。

没有箭头回放页面。CSV/JSON 可以直接由 Python、表格软件或诊断工具读取。测试命令 `python scripts/test_recording.py` 需要 PATH 中的 ffmpeg/ffprobe，仅生成合成画面和声音，不连接手机；产品运行不需要这两个命令行程序。
